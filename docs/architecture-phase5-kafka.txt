CURRENT EVENT FLOW

1. API receives product update.
2. Spring Boot updates PostgreSQL.
3. PostgreSQL transaction completes.
4. Producer publishes a Kafka event.
5. Kafka stores the event.
6. Consumer receives the event.
7. Consumer reads authoritative data from PostgreSQL.
8. Consumer updates Elasticsearch.
9. Search reflects the change.

RECOVERY

The application still performs a full PostgreSQL
to Elasticsearch synchronization during startup.


PRODUCTION IMPROVEMENT

Current flow:

database commit
then
Kafka publish

There is a small failure window between those
operations.

A future improvement is:

Transactional Outbox Pattern

or

Change Data Capture (CDC)

so the database change and event publication can
be made reliable across crashes and restarts.
